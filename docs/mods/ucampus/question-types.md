## 2. 模型上下文规则

**不能只发题干和选项。**

### 2.1 阅读题

必须附：

- 文章正文
- Directions
- 题干
- 选项

实现：页面 Agent 的 `pageContextForModel()` 从 `main` / `.question-wrap` 等容器提取正文，去掉题目、选项、目录、导航、评论和面板，作为 `/api/answer` 的 `context`。

### 2.2 听力题

必须附：

- 音频转写文本
- 题目和选项
- 多题页面要带当前页所有题目（逐题调用时，至少每道题都带同一份转写）

实现：`questionForModel` 追加 `[听力原文]`，并同时把转写放入 `context`。

### 2.3 视频题

先提取视频音轨并转写；只有拿到视频文本后才请求答案。

必须附：

- 视频音轨转写
- 题干和选项
- 视频相关 Directions

实现：`transcribeVideoAudio()` 后：

- `questionForModel` 追加 `[视频内容转写]`
- `/api/answer` 的 `context` 再带一份 `[视频内容转写]`
- 如果视频音轨无法下载/转写，停在当前页，不根据题干和选项猜答案

### 2.4 多题一页

同一页有多道选择题时：

- 逐组作答
- 每组都携带同一份文章/音频/视频上下文
- 不能只用“当前题干 + 当前选项”覆盖掉阅读材料

### 2.5 填空/排序

- 填空：附文章正文和摘要上下文
- 排序：附文章正文，让模型按文章顺序输出字母序列

## 3. 排序题的当前策略

排序组件对合成鼠标事件不稳定，自动拖拽会打乱页面顺序。

当前源码策略：

```text
模型给出顺序
  → 面板/日志显示“正确答案：C → A → D → F → B → E”
  → 不自动拖拽
  → 等用户手动拖拽后提交
```

优点：不会破坏页面状态。缺点：不是完全自动。

## 4. 安全边界

以下操作永远不自动执行：

- 提交
- 交卷
- 发布讨论
- 评分提交
- 结束/完成课程

讨论区只填内容；口语只写上传框；排序只显示答案；roleplay/dubbing 直接停止。

## 5. 已知问题

1. 原生 radio 多组仍可能走 AI 兜底，未做批量结构化作答。
2. 多题一页时，部分页面的题目组选择器不是 `.question-common-abs-choice`，需要按实际模板补。
3. 听力/视频题依赖 ASR；打包版未内置 `faster-whisper`。
4. 视频编解码不支持时只能跳过，不能真正“看完”。
5. 排序自动拖拽已关闭，后续如果恢复，需要独立适配器与录制回放测试。
